# Логика расчёта юнит-экономики Wildberries

Этот документ описывает фактическую логику текущего веб-калькулятора WB Uzbekistan. Основной акцент — блок логистики: доставка, запас, процент выкупа, возвраты, историческая калибровка, хранение и платная приёмка.

> Важно: это описание реализации в коде, а не официальных тарифов Wildberries. Прогноз доставки построен по регрессии загруженных отчётов WB и затем корректируется историческим коэффициентом.

## 1. Общая схема расчёта

Расчёт одной успешной продажи проходит по цепочке:

```text
Габариты товара
    ↓
Объём в литрах
    ↓
Базовая доставка по регрессионной формуле
    ↓
Запас на колебания тарифа
    ↓
Пересчёт с учётом процента выкупа и возвратов
    ↓
Исторический коэффициент логистики
    ↓
Итоговая логистика на одну успешную продажу
```

Отдельно рассчитываются:

- хранение;
- BF — прочие удержания WB;
- платная приёмка;
- комиссия WB;
- эквайринг;
- реклама;
- НДС;
- себестоимость.

Логистика, хранение, BF и приёмка уменьшают сумму к перечислению продавцу и чистую прибыль, но в интерфейсе являются разными статьями.

## 2. Входные параметры

### Параметры логистического блока

| Параметр | Обозначение | Единица | Значение по умолчанию |
|---|---:|---:|---:|
| Длина товара | `lengthCm` | см | из основной калькуляции |
| Ширина товара | `widthCm` | см | из основной калькуляции |
| Высота товара | `heightCm` | см | из основной калькуляции |
| Процент выкупа | `buyoutPct` | % | 87% |
| Запас к доставке | `safetyPct` | % | 10% |
| Фиксированный возврат | `returnFixed` | сум/возврат | 7 200 |
| Тариф хранения | `storageTariff` | сум/л/день | 42 |
| Оборачиваемость | `turnoverDays` | дней | 30 |
| Платная приёмка | `acceptanceUzs` | сум/ед. | 0 |
| Цена продажи | `priceUzs` | сум/ед. | 0 |
| Артикул | `sku` | строка | из связанного товара |

### Остальные параметры юнит-экономики

| Параметр | Обозначение | Единица | Значение по умолчанию |
|---|---:|---:|---:|
| Комиссия WB | `commPct` | % цены | 25% |
| Эквайринг | `acquiPct` | % цены | 3% |
| ДРР | `drrPct` | % цены | 0% |
| СПП | `sppPct` | % | 24,7% |
| НДС | `vatPct` | % | 12% |
| Курс | `exchangeRate` | сум за 1 ₽ | 168 |
| Себестоимость | `costUzs` | сум/ед. | 0 |

СПП влияет только на показываемую покупательскую цену. Комиссия, эквайринг, реклама и остальные удержания в текущем прогнозе считаются от полной цены продавца `priceUzs`, а не от цены после СПП.

## 3. Расчёт объёма

Объём рассчитывается из габаритов товара:

```text
litersRaw = lengthCm × widthCm × heightCm / 1000
liters = max(0, litersRaw)
```

Почему делим на 1000:

```text
1 литр = 1000 см³
```

Пример:

```text
40 см × 30 см × 10 см / 1000 = 12 л
```

В WB-блоке нет отдельного ручного поля литража. Значение переносится из основной калькуляции в скрытое поле. Если габариты не перенесены и литраж равен нулю, логистика принудительно равна нулю.

## 4. Базовая стоимость доставки

Доставка прогнозируется по двум регрессионным формулам. Обозначим:

- `L` — объём товара в литрах;
- `delivery` — базовая доставка одного заказа в сумах.

### Товар объёмом до 1,5 литра включительно

```text
delivery = round(1 403 + 4 600 × L)
```

### Товар объёмом больше 1,5 литра

```text
delivery = round(4 584 + 2 068 × L)
```

В коде:

```text
если L ≤ 1,5:
    delivery = round(1 403 + 4 600 × L)
иначе:
    delivery = round(4 584 + 2 068 × L)
```

Формулы получены по фактическому отчёту WB. В комментарии к коду указаны `R² ≈ 0,98` и ориентировочная погрешность около 4%.

### Особенность границы 1,5 литра

На границе есть разрыв:

```text
при L = 1,5:
delivery = 1 403 + 4 600 × 1,5 = 8 303 сум

сразу после L = 1,5:
delivery ≈ 4 584 + 2 068 × 1,5 = 7 686 сум
```

То есть при переходе во второй сегмент прогноз сначала уменьшается примерно на 617 сум. Это фактическое поведение текущей формулы.

## 5. Запас к доставке

К базовой доставке добавляется буфер на дальние склады и колебания тарифа:

```text
deliverySafe = round(delivery × (1 + safetyPct / 100))
```

При стандартном запасе 10%:

```text
deliverySafe = round(delivery × 1,10)
```

Запас применяется только к прямой доставке. Фиксированная обратная логистика на этот процент не увеличивается.

## 6. Процент выкупа и обратная логистика

Калькулятор показывает расходы в пересчёте на одну успешную продажу. Поэтому он учитывает не только выкупленный заказ, но и дополнительные попытки доставки и возвраты.

Обозначения:

```text
r = buyoutPct / 100
R = returnFixed
```

Внутри функции значение `r` не может быть ниже `0,01`.

### Полная базовая формула

```text
baseLogistics =
    round(deliverySafe / r + R / r − R)
```

Та же формула в более наглядном виде:

```text
baseLogistics =
    round(
        deliverySafe / r
        + R × (1 / r − 1)
    )
```

### Смысл частей формулы

Прямая доставка:

```text
deliverySafe / r
```

Это стоимость всех попыток доставки, необходимая в среднем для получения одного выкупа.

Ожидаемые возвраты:

```text
R × (1 / r − 1)
```

Это ожидаемое количество невыкупленных заказов на одну успешную продажу, умноженное на стоимость одного возврата.

### Проверка крайних случаев

При выкупе 100%:

```text
r = 1
baseLogistics = deliverySafe
возвратная часть = 0
```

Чем ниже выкуп, тем быстрее растут обе части:

- требуется больше прямых доставок на одну продажу;
- появляется больше обратных доставок.

## 7. Историческая калибровка логистики

После базового расчёта применяется коэффициент, полученный из фактических отчётов WB:

```text
logisticsUzs = round(baseLogistics × logisticsCoef)
```

Смысл коэффициента:

```text
logisticsCoef =
    фактическая логистика из отчёта WB
    / базовый прогноз калькулятора
```

- коэффициент меньше 1 уменьшает прогноз;
- коэффициент больше 1 увеличивает прогноз;
- коэффициент 1 оставляет базовую формулу без изменений.

Коэффициент умножает всю сумму `baseLogistics`, включая расчётную обратную логистику.

### Как выбирается калибровка

Фактическая цепочка текущего интерфейса:

```text
SKU с достаточной историей
    ↓ если не найден
Категория товара
    ↓ если не найдена
Глобальная калибровка
```

SKU-калибровка используется только при исторической выборке не менее 5 единиц. Текущий интерфейс получает коэффициент из legacy-калибровки и передаёт его в v4 как ручной override.

Глобальный коэффициент, фактически используемый для неизвестного SKU:

```text
logisticsCoef = 0,9515
```

### Категорийные коэффициенты

| Категория | Коэффициент логистики |
|---|---:|
| Крашёное постельное | 1,0192 |
| Простыни 160×200 | 0,7116 |
| Наволочки 70×70 | 0,9487 |
| Наволочки 50×70 | 0,9002 |
| Простыни 140×200 | 0,9771 |
| Простыни 180×200 | 1,0021 |
| Kids | 1,0552 |
| Сатин / stripe | 0,8847 |

Если для конкретного SKU есть своя калибровка с достаточной выборкой, используется коэффициент SKU, а не коэффициент категории.

## 8. Итоговая формула логистики

В одной записи:

```text
L = max(0, lengthCm × widthCm × heightCm / 1000)

delivery =
    если L ≤ 1,5:
        round(1 403 + 4 600 × L)
    иначе:
        round(4 584 + 2 068 × L)

deliverySafe =
    round(delivery × (1 + safetyPct / 100))

r = max(0,01, buyoutPct / 100)

baseLogistics =
    если L > 0:
        round(deliverySafe / r + returnFixed / r − returnFixed)
    иначе:
        0

logisticsUzs =
    round(baseLogistics × logisticsCoef)
```

`logisticsUzs` — сумма, которая отображается в строке «Логистика» и вычитается из выплаты продавцу.

## 9. Подробный пример расчёта логистики

Исходные данные:

```text
Объём:                 3,24 л
Процент выкупа:        87%
Запас:                 10%
Возврат:               7 200 сум
Глобальный коэффициент: 0,9515
```

Шаг 1. Объём больше 1,5 л:

```text
delivery =
    round(4 584 + 2 068 × 3,24)
    = round(11 284,32)
    = 11 284 сум
```

Шаг 2. Добавляем запас:

```text
deliverySafe =
    round(11 284 × 1,10)
    = 12 412 сум
```

Шаг 3. Пересчитываем на один успешный выкуп:

```text
r = 87 / 100 = 0,87

baseLogistics =
    round(12 412 / 0,87 + 7 200 / 0,87 − 7 200)
    = round(15 342,53)
    = 15 343 сум
```

Шаг 4. Применяем исторический коэффициент:

```text
logisticsUzs =
    round(15 343 × 0,9515)
    = 14 599 сум
```

Итоговая прогнозная логистика на одну успешную продажу — `14 599 сум`.

## 10. Хранение

Хранение не входит в строку «Логистика». Оно считается и вычитается отдельно.

### Расчёт по объёму и дням

```text
storageByLiters =
    round(liters × storageTariff × turnoverDays)
```

При тарифе 42 сум/л/день:

```text
storageByLiters =
    round(liters × 42 × turnoverDays)
```

### Исторический минимум

Дополнительно рассчитывается минимум хранения как доля цены:

```text
storageByPct =
    round(priceUzs × storagePctOfPrice / 100)
```

В текущей глобальной калибровке:

```text
storagePctOfPrice = 1,15%
```

### Итоговое хранение

```text
storageTotal =
    max(storageByLiters, storageByPct)
```

Пример при цене 300 000 сум, объёме 3,24 л и оборачиваемости 30 дней:

```text
storageByLiters =
    round(3,24 × 42 × 30)
    = 4 082 сум

storageByPct =
    round(300 000 × 1,15%)
    = 3 450 сум

storageTotal =
    max(4 082, 3 450)
    = 4 082 сум
```

Даже если литраж или количество дней равно нулю, при положительной цене хранение будет не ниже 1,15% цены.

## 11. Платная приёмка

Платная приёмка вводится напрямую:

```text
acceptanceUzs = max(0, введённая сумма)
```

Единица измерения — сум на одну единицу товара.

Приёмка:

- не входит в `logisticsUzs`;
- не умножается на процент выкупа;
- не умножается на коэффициент логистики;
- отдельно вычитается из суммы к перечислению;
- сейчас не имеет отдельной строки в детализации результата.

## 12. BF — прочие удержания

BF рассчитывается как фиксированный исторический прогноз на одну продажу:

```text
bfForecastUzs = round(bfPerUnit)
```

Глобальное значение:

```text
bfPerUnit = 3 071 сум
```

Значение может заменяться калибровкой категории или SKU. BF не входит в строку «Логистика», но отдельно уменьшает выплату и прибыль.

Категорийные значения BF:

| Категория | BF, сум/продажу |
|---|---:|
| Крашёное постельное | 5 617 |
| Простыни 160×200 | 1 893 |
| Наволочки 70×70 | 949 |
| Наволочки 50×70 | 854 |
| Простыни 140×200 | 1 589 |
| Простыни 180×200 | 1 962 |
| Kids | 3 840 |
| Сатин / stripe | 6 380 |

## 13. Что входит в блок логистики

### В строку «Логистика» входит

- базовая доставка по объёму;
- запас к прямой доставке;
- увеличение числа доставок из-за неполного выкупа;
- ожидаемая фиксированная стоимость возвратов;
- исторический коэффициент логистики.

### В строку «Логистика» не входит

- хранение;
- платная приёмка;
- BF;
- комиссия WB;
- эквайринг;
- реклама;
- НДС;
- себестоимость;
- СПП;
- штрафы и другие удержания.

Хранение, приёмка и BF относятся к связанным операционным расходам WB, но в расчёте являются отдельными статьями.

## 14. Сумма к перечислению продавцу

Обозначения:

```text
commission = round(priceUzs × commPct / 100)
acquiring  = round(priceUzs × acquiPct / 100)
ads        = round(priceUzs × drrPct / 100)
```

Сумма к перечислению:

```text
toSeller =
    priceUzs
    − commission
    − acquiring
    − ads
    − logisticsUzs
    − bfForecastUzs
    − storageTotal
    − acceptanceUzs
```

Таким образом, каждый дополнительный 1 сум логистики, хранения, BF или приёмки уменьшает сумму к перечислению на 1 сум.

## 15. НДС и чистая прибыль

Исходящий НДС выделяется из полной цены продавца:

```text
outputVat =
    round(priceUzs × vatPct / (100 + vatPct))
```

Входящий НДС по себестоимости:

```text
inputVatCost =
    round(costUzs × vatPct / (100 + vatPct))
```

Если из связанной калькуляции передан рассчитанный входящий НДС, он имеет приоритет над автоматическим выделением из себестоимости.

В текущем UI входящий НДС по услугам WB не засчитывается:

```text
inputVatServices = 0
```

НДС к оплате:

```text
vatPayable = outputVat − inputVatCost
```

Чистая прибыль:

```text
netProfit =
    round(toSeller − costUzs − vatPayable)
```

Маржа:

```text
marginPct =
    netProfit / priceUzs × 100
```

ROI:

```text
roiPct =
    netProfit / costUzs × 100
```

При нулевой цене маржа принудительно равна нулю. При нулевой себестоимости ROI принудительно равен нулю.

## 16. Важные технические особенности

### Нулевые значения некоторых полей заменяются дефолтами

В текущем интерфейсном коде используется конструкция `value || default`. Поэтому введённый ноль фактически заменяется значением по умолчанию для:

| Поле | Введено | Фактически используется |
|---|---:|---:|
| Запас | 0% | 10% |
| Возврат | 0 сум | 7 200 сум |
| Тариф хранения | 0 | 42 сум/л/день |
| НДС | 0% | 12% |

Это отличается от ограничений HTML-полей, где ноль разрешён.

### При нулевом литраже

```text
logisticsUzs = 0
```

Свободный член регрессии не применяется. Но хранение всё равно может составить 1,15% цены.

### Справочник тарифов по объёму

Редактируемая таблица в интерфейсе:

- хранит названия товаров и объёмы в `localStorage`;
- сортируется по объёму;
- показывает доставку по той же регрессионной формуле;
- не является lookup-таблицей;
- не выбирает тариф для текущего товара;
- не меняет скрытый литраж текущего расчёта.

Фактический расчёт всегда использует литраж, перенесённый из габаритов товара.

### Смешение legacy и v4-калибровок

В проекте существуют два набора калибровок. Хотя функция v4 умеет выбирать свой коэффициент по SKU, категории и глобальному уровню, текущий интерфейс передаёт коэффициент legacy как override. Поэтому числовой коэффициент логистики обычно берётся из legacy-файла.

### Резервный режим

Если модуль v4 не загрузился, калькулятор использует fallback:

```text
logisticsCoef = 1
storageTotal = round(liters × storageTariff × turnoverDays)
```

В fallback:

- историческая калибровка логистики не применяется;
- минимальное хранение 1,15% цены не применяется;
- BF всё ещё берётся из legacy-калибровки;
- входящий НДС услуг WB равен нулю.

## 17. Основные исходники

Актуальная логика распределена по файлам:

- `script.js` — получение входных значений, объём, базовые формулы доставки и возвратов, передача данных в v4;
- `wb-uz-calibration.js` — фактически используемые legacy-коэффициенты по SKU и категориям;
- `wb-uz-calibration-v4.js` — итоговый прогноз, хранение, выплата, НДС и прибыль;
- `index.html` — поля ввода и вывод детализации.

Файл `wb-unit-economics-logic.js` является отдельной старой копией логики и текущим интерфейсом не вызывается.

## 18. Краткая формула для внедрения в другой калькулятор

```text
liters = max(0, lengthCm × widthCm × heightCm / 1000)

delivery =
    round(1 403 + 4 600 × liters), если liters ≤ 1,5
    round(4 584 + 2 068 × liters), если liters > 1,5

deliverySafe =
    round(delivery × (1 + safetyPct / 100))

buyoutRate =
    max(0,01, buyoutPct / 100)

baseLogistics =
    0, если liters ≤ 0
    round(
        deliverySafe / buyoutRate
        + returnFixed × (1 / buyoutRate − 1)
    ), если liters > 0

logistics =
    round(baseLogistics × logisticsCoef)

storage =
    max(
        round(liters × storageTariff × turnoverDays),
        round(priceUzs × 1,15%)
    )

toSeller =
    priceUzs
    − commission
    − acquiring
    − ads
    − logistics
    − BF
    − storage
    − acceptance

netProfit =
    round(toSeller − costUzs − vatPayable)
```
